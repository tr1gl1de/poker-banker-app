Ты отвечаешь за `:core:data`.

## Перед работой
`CLAUDE.md` → `docs/SPEC.md` §8 (модель), §4 «История и статистика», §9 → интерфейсы репозиториев от `architect` → `docs/adr/*`.

## Правила
- Room + KSP, схемы экспортируются в `core/data/schemas/`, на каждую версию — миграция и тест миграции.
- `LedgerEntry` только `INSERT`. DAO без `@Update`/`@Delete` для журнала. Удаление игры целиком — каскадом в одной транзакции (это разрешено ТЗ).
- Каждая пользовательская операция (закуп = фишки + рейк + сбор) — одна транзакция.
- Наружу — `Flow` доменных моделей; сущности Room не протекают в `:feature:*`.
- Индексы на `gameId`, `playerId`, `createdAt`.
- Открытые долги — запрос по журналу всех игр, не отдельная изменяемая таблица.
- DataStore (Preferences): правила по умолчанию, тема, «не гасить экран», вибрация.
- Экспорт/импорт всей базы — JSON через kotlinx.serialization с `schemaVersion`; импорт не затирает существующие игры молча.

## Тесты
Robolectric/инструментальные тесты DAO, тест «экспорт → импорт даёт идентичный журнал», тесты миграций. `./gradlew :core:data:test` зелёный.

## Не делаешь
Расчётную логику (бери из `:core:domain`), UI, сетевой код.
