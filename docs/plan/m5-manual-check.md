# M5. Ручная проверка передачи комнаты на двух телефонах

Статус: чек-лист для владельца (roadmap M5.5). Прогон — на реальных телефонах, эмулятор Nearby не заменяет.
**Передача по воздуху между двумя телефонами ещё не проверена** — у агента был один телефон (см. «Прогон на одном телефоне»).

## Прогон на одном телефоне (агент, 2026-11-02, Redmi 6A, Android 9, debug)

- [x] «Передать комнату» со стола: карточка «Нужен доступ…» → «Разрешить» → системный запрос геолокации (без запроса при старте).
- [x] Служба геолокации выключена → «Включите геолокацию…»; после включения «Попробовать ещё раз» → «Ищем телефон рядом…», Nearby начал поиск (BLE + Wi-Fi LAN, logcat).
- [x] «Принять игру»: «Ждём телефон банкира…», Nearby начал рекламу (BLE + Wi-Fi LAN), без падений.
- [x] Через минуту без получателя — «Не получилось передать…» + «Попробовать ещё раз» / «Отправить файлом».
- [x] «Отправить файлом» → «Кому передаёте игру?» → Sharesheet (Telegram, Gmail, Быстрая отправка, Диск, «Копировать в…», Bluetooth).
- [x] Файл, открытый в Feltbook (ACTION_SEND), → «Принять игру» в режиме файла: «Файл: <имя>.feltbook», сводка, «Я играю как…». Самому себе больше не отправить — Feltbook исключён из Sharesheet.
- [x] ACTION_VIEW `content://` без доступа → «Это не файл Feltbook», без падения.
- [x] Шаблон: История → закрытая игра → «⋮» → «Передать шаблон новому банкиру» → файлом → «Принять шаблон» → «Новая игра» с подсказкой «Шаблон от … · игроки: …».
- [ ] Всё остальное ниже — на двух телефонах (владелец).

## Телефоны

| Метка | Android | Google Play Services | Что проверяет |
| --- | --- | --- | --- |
| A | 8.0–8.1 (API 26–27) | есть | minSdk, геолокация как разрешение и как служба, классический Bluetooth |
| B | 12 (API 31–32) | есть | `BLUETOOTH_SCAN/ADVERTISE/CONNECT` + точная геолокация |
| C | 14+ (API 34+) | есть | `NEARBY_WIFI_DEVICES` без геолокации, Wi-Fi Direct/точка доступа |
| D | любой | **нет** (Huawei без GMS, LineageOS без microG или GMS отключены в настройках) | сразу файл |

Пары: A ↔ C, B ↔ C, C ↔ C (если есть второй 14+), D ↔ C (только файл). В каждой паре — оба направления.

## Подготовка

- [ ] Свежая установка на оба телефона (`./gradlew installDebug`), разрешения не выданы.
- [ ] Bluetooth и Wi-Fi включены; интернет выключен на обоих (режим полёта + вручную включить Bluetooth и Wi-Fi) — передача обязана идти без сети.
- [ ] На отправителе идёт игра по сквозному примеру ТЗ §3.6 (6 игроков, докупы, один «в долг», чаевые) — минимум 20 записей журнала. Для пакета > 32 КБ: отдельная игра с 10 игроками и ~200 записями (докупы/отмены), проверка лимита BYTES.
- [ ] Запомнить на отправителе: «Наличные в кассе», «Рейк заведению», «Долги игроков», «Мой доход банкира», число записей.

## 1. Посреди игры, по воздуху (сценарий 1)

1. [ ] Получатель: Главная → «Принять игру». Если имя банкира не задано — «Как вас зовут?», ввести «Влад» → «Ждать телефон банкира».
2. [ ] Получатель: карточка «Нужен доступ к Bluetooth и Wi-Fi рядом» → «Разрешить» → системный запрос (A: геолокация; B: «Устройства поблизости» + геолокация; C: «Устройства поблизости»). Разрешения **не** запрашивались при запуске приложения.
3. [ ] A: если служба геолокации выключена — баннер «Включите геолокацию…»; после включения «Попробовать ещё раз» работает.
4. [ ] Получатель: «Ждём телефон банкира…».
5. [ ] Отправитель: Стол → «Передать комнату» → вкладка «Отдать игру» → «Разрешить» → «Ищем телефон рядом…» → «Телефон: Влад» появляется сам (один телефон — соединение без выбора).
6. [ ] На обоих телефонах одинаковые 4 цифры; TalkBack читает «Код 4 7 1 9».
7. [ ] Акт на отправителе совпадает с табло стола: касса, рейк, долги, «Долг вышедшим» (если есть), доход; «Передаётся: N игроков · N фишек · N записей журнала».
8. [ ] «Оставить доход себе»: доступен только если касса покрывает рейк; «Отдать наличными» уменьшается на доход. Если недоступен — подпись «— после расчёта долгов», серый.
9. [ ] Получатель: «Код совпадает» → «Ждём, пока второй телефон подтвердит код».
10. [ ] Отправитель: удержание «Код совпадает — удерживайте» 0,6 с (короткое нажатие не срабатывает) → «Отправляем…» → «Ждём, пока новый банкир примет игру…». Игра на отправителе **ещё активна** (вернуться назад — стол работает).
11. [ ] Получатель: «Игра «…» от Андрей»: игроков за столом, фишек в игре, касса = «Отдать наличными» отправителя. «Я играю как…» — по умолчанию «Не играю»; выбрать игрока.
12. [ ] Получатель: удержание «Принять игру» → открывается стол; банкир — «Влад»; выбранный игрок помечен «БАНКИР»; в журнале строка «Игра принята от Андрей».
13. [ ] Отправитель: «Игра передана · Новый банкир: Влад» → «На главную»; в Истории игра «Передана», открывается только для чтения, долги этой игры не в «Открытых долгах».
14. [ ] Получатель продолжает игру: докуп, выход — доход нового банкира считается отдельно (Настройки/Итог показывают доход двух банкиров раздельно).
15. [ ] Повторить шаги 1–13 с большой игрой (> 32 КБ) — пакет доходит целиком, прогресс «Отправляем…» растёт.

## 2. Сбои по воздуху

- [ ] «Код другой — отмена» на получателе → у отправителя баннер «Не получилось передать…» + «Попробовать ещё раз» / «Отправить файлом».
- [ ] «Код другой — отмена» на отправителе → поиск начинается заново, получатель снова ждёт.
- [ ] Отправитель ищет, получатель не открыт → через ~1 минуту «Не получилось передать…» + «Отправить файлом».
- [ ] Выключить Bluetooth на получателе во время «Отправляем…» → у отправителя ошибка, игра у него активна, у получателя ничего не записано.
- [ ] Обрыв **после** доставки (получатель видит сводку, затем выключить Wi-Fi и Bluetooth на отправителе) → получатель всё равно может «Принять игру»; отправитель видит «Связь прервалась после отправки» + «Новый банкир уже принял игру?» → «Да, принял» → игра «Передана». Повторная отправка («Попробовать ещё раз») шлёт тот же пакет — у получателя без дубля (повторный приём — без изменений).
- [ ] Получатель «Не принимать» → у отправителя «Новый банкир не стал принимать игру.», ничего не записано.
- [ ] Отказ в системном запросе разрешений → «Без доступа передать по воздуху не получится…» + «Разрешить» + «Отправить файлом».
- [ ] Свернуть приложение получателя во время ожидания и вернуться — состояние сохраняется.
- [ ] На получателе уже идёт своя игра → «Принять игру» даёт «На этом телефоне уже идёт игра — сначала закройте её», ничего не записано.

## 3. Файлом (запасной путь; телефон D — обязательно)

1. [ ] D (отправитель): «Отдать игру» → сразу «На этом телефоне нет сервисов Google…» + «Отправить файлом» (без поиска и запроса разрешений).
2. [ ] «Отправить файлом» → «Кому передаёте игру?» → «Влад» → Sharesheet: Telegram, Quick Share/Nearby Share, почта, «Файлы». Имя файла — «<название игры>.feltbook».
3. [ ] После Sharesheet — «Файл отправлен?»: «Ещё нет» — игра активна; повторная отправка тому же имени даёт тот же пакет. «Да, отправлен» — игра «Передана».
4. [ ] C (получатель): открыть файл из Telegram / «Файлов» / вложения почты → открывается Feltbook на «Принять игру» со сводкой и «Файл: <имя>»; «Принять игру» → стол, ACK не нужен.
5. [ ] Открыть тот же файл повторно → без новых записей (Identical), без ошибки.
6. [ ] Отправитель открывает **свой** файл через «Файлы» (сохранённый «Копировать в…»), если получатель так и не принял (QUESTIONS №13) → игра снова активна у отправителя. В Sharesheet самого Feltbook нет.
7. [ ] Старое расширение `.pokerbank` (переименовать файл) открывается так же.
8. [ ] Испорченный файл (изменить одну цифру суммы в текстовом редакторе) → «Файл повреждён — попросите отправить его ещё раз».
9. [ ] Чужой файл (фото, .json не Feltbook) → «Это не файл Feltbook»; резервная копия `.feltbook` (BACKUP) → «Это резервная копия — восстановите её в «Настройки → Резервная копия»».

## 4. После расчёта — шаблон (сценарий 2, QUESTIONS №5)

- [ ] Закрыть игру с долгом на отправителе → История → игра → «Передать шаблон» (или Handover с id закрытой игры) → «♦ Шаблон новой игры»: правила, число имён, «Долги этой игры остаются у вас».
- [ ] Код → удержание → у получателя «Шаблон новой игры от Андрей» → «Принять шаблон» → «Новая игра» с правилами отправителя и подсказками имён.
- [ ] У отправителя игра осталась «Закрыта» (не «Передана»), долг — в его «Открытых долгах».
- [ ] То же файлом (без вопроса «Кому передаёте» и без «Файл отправлен?»).

## 5. Доступность и вид

- [ ] Шрифт 200 % (Настройки Android): код, акт, суммы не переносятся и не обрезаются; кнопки читаемы.
- [ ] TalkBack: «Код 4 7 1 9», суммы акта «950 рублей», «Оставить доход себе» — переключатель с состоянием; удержание — через действие «Подтвердить».
- [ ] Светлая тема — контраст цифр кода и акта.
- [ ] Манифест собранного APK (`aapt dump permissions`): нет `INTERNET`; есть `ACCESS_NETWORK_STATE` (добавляет Nearby), `BLUETOOTH*`, `NEARBY_WIFI_DEVICES`, `ACCESS_FINE_LOCATION` с `maxSdkVersion=32`.

## Известные риски для прогона

- `BLUETOOTH_SCAN` объявлен без `neverForLocation` (QUESTIONS №22): с флагом Android отфильтровывает BLE-объявления Nearby. `NEARBY_WIFI_DEVICES` — с флагом.
- Nearby не сообщает среду соединения (Bluetooth / Wi-Fi Direct), поэтому подпись устройства — «найден рядом» без среды (в макете — «· Wi-Fi Direct»).
