# Дорожная карта M1–M6

Каждая задача: исполнитель → `qa-engineer` → `code-reviewer` → коммит (CLAUDE.md). Контракт домена — `docs/plan/m1-domain.md`; решения — ADR 0005–0007.

## Правило параллельности

Машина держит **одну Gradle-сборку за раз**. Поэтому:
- агенты, которые собирают (`domain-engine`, `data-layer`, `compose-ui`, `transfer`, `poker-odds`, `build-release`, `qa-engineer`), работают **по очереди**: следующий стартует, когда предыдущий сдал контракт;
- параллельно со сборщиком можно запускать только тех, кто не собирает: `architect`, `code-reviewer` (читает diff прошлой задачи);
- «Можно параллельно» ниже означает: задачи **независимы по коду** и их можно чередовать в любом порядке или давать двум агентам, если один пишет код без сборки, а собирает строго после другого. По умолчанию — последовательно, в указанном порядке.

## M0. Скелет (идёт, `build-release`)

Требования к скелету от этого плана (если ещё не учтены — передать `build-release`):
- `:core:domain` (KMP, `jvm()`): `commonMain` — `kotlinx-coroutines-core`, `kotlinx-serialization-json`, плагин `org.jetbrains.kotlin.plugin.serialization`; `commonTest` — `kotlin-test`; JUnit Platform на jvm; Kover с порогом 95 % для модуля.
- Opt-in на модуль, если в Kotlin 2.4 ещё нужен: `kotlin.uuid.ExperimentalUuidApi`, `kotlin.time.ExperimentalTime`.
- `:core:data` — Room (схемы в `core/data/schemas/`), DataStore Preferences, kotlinx-serialization, Robolectric.
- `:core:ui` — шрифты OFL в `res/font`.
