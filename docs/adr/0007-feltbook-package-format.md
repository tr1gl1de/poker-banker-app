# 0007. Формат пакета `.feltbook` и протокол передачи

Статус: принято · 2026-11-02

## Контекст
ТЗ §6: пакет — JSON (kotlinx.serialization) с версией схемы и SHA-256, тот же формат у файла-фолбэка; ТЗ §4 — резервная копия всей базы; ADR 0001 — формат в общем коде, чтобы его читала будущая iOS-версия. `:core:transfer` — Android-модуль (Nearby), поэтому формат там жить не может.

## Решение
- DTO, кодек и SHA-256 — в `:core:domain`, пакет `app.feltbook.core.domain.transfer`. `:core:transfer` занимается только транспортом (Nearby, Sharesheet, файлы), `:core:data` — резервной копией через тот же кодек.
- Конверт: `{format: "feltbook", schemaVersion: 1, kind: HANDOVER|TEMPLATE|BACKUP, createdAt, sha256, payload}`, где `payload` — **JSON-строка**, `sha256` — hex SHA-256 от её UTF-8 байтов. Хеш не зависит от повторной сериализации (порядок ключей, пробелы).
- DTO отделены от доменной модели: id — строки UUID, время — epoch ms, перечисления — строки с явным маппингом. Переименование в домене не ломает файлы молча.
- Чтение: формат → версия (`> 1` — «обновите приложение») → хеш → структура → `LedgerValidator`. Внутри версии неизвестные ключи — ошибка; любое изменение схемы повышает `schemaVersion`, читатель поддерживает все прежние.
- SHA-256 — своя реализация на чистом Kotlin (~100 строк, векторы NIST в тестах), без новой зависимости.
- Расширение `.feltbook`, импорт принимает и `.pokerbank` (ADR 0003).
- **Протокол передачи посреди игры:** отправитель готовит `PreparedHandover` (в памяти: `INCOME_TAKEN?` + акт + статус HANDED_OVER) и шлёт пакет; получатель проверяет, показывает сводку, по «Принять» коммитит и отвечает ACK; отправитель коммитит **те же** записи (те же id) только после ACK. Для файла ACK заменяет явное «Файл отправлен, игра у Влада» (необратимое действие, диалог).
- **Повторный импорт той же игры** (игру вернули первому банкиру, импорт резервной копии): если локальный журнал — префикс входящего, хвост дописывается (Extend), иначе конфликт — локальное не трогаем. Журнал по-прежнему только дописывается.
- **Шаблон после расчёта** (ТЗ §6, сценарий 2): `TEMPLATE` = правила + имена; у отправителя игра остаётся CLOSED, её долги — у него (QUESTIONS №5).
- Nearby `Payload.fromBytes` ограничен ~32 КБ, а большая игра больше: транспорт шлёт `Payload.fromStream`/файл или режет на части (решает `transfer`).

## Альтернативы
- Подпись по канонической сериализации объекта: хрупко между версиями библиотеки и платформами.
- `@Serializable` прямо на доменных классах: меньше кода, но формат файла меняется от любого рефакторинга модели.
- DTO в `:core:transfer`: недоступны iOS и `:core:data` без зависимости data → transfer.

## Последствия
- `:core:domain` зависит от `kotlinx-serialization-json` (уже в стеке).
- Тест «экспорт → импорт идентичен» (ТЗ §9) — в `commonTest` домена плюс интеграционный в `:core:data`.
