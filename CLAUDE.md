# Feltbook — банк покерного стола (Android)

Офлайн-приложение для банкира в домашней игре в техасский холдем: закупы и докупы фишек, долги, рейк заведению, сбор банкира, чаевые, расчёт при выходе, итог игры, передача комнаты на другой телефон, история и статистика. Open source.

## Источники правды

| Что | Где | Правило |
| --- | --- | --- |
| Требования и формулы | `docs/SPEC.md` | Читать перед любой задачей. Расхождение кода и ТЗ — баг кода, если в ТЗ не сказано иное |
| Экраны | `docs/mockups/*.dc.html` | Отступы, размеры, цвета и тексты брать из inline-стилей макетов |
| Дизайн-токены | `docs/DESIGN.md` | Цвета, шрифты, формы, компоненты. Других цветов в коде нет |
| Решения по архитектуре | `docs/adr/NNNN-*.md` | Любое отступление от этого файла — через ADR |

Если ТЗ молчит или противоречит само себе — не угадывай: запиши вопрос в `docs/QUESTIONS.md` и сделай самый безопасный вариант (ничего не теряется, всё обратимо).

## Железные правила

1. **Деньги и фишки — только `Long` в рублях.** Никаких `Double`/`Float`. 1 фишка = 1 ₽. Проценты: `round(amount * percent / 100)` математически, до рубля.
2. **Журнал только дописывается.** Балансы не хранятся — вычисляются из `LedgerEntry`. Исправление ошибки = отменяющая запись (`REVERSAL`), не `UPDATE`/`DELETE`. В интерфейсе это «Отменено», слово «сторно» не используем нигде.
3. **Правила игры — слепок.** `GameRules` копируется в игру при создании; смена настроек по умолчанию не трогает начатые и прошлые игры.
4. **Офлайн.** Разрешения `INTERNET` в манифесте нет. Данные покидают телефон только через передачу комнаты или экспорт, по явному действию пользователя.
5. **Сверка фишек — инвариант.** Сумма закупов = сумма фишек на выходе. Расхождение показывается и не даёт закрыть игру без подтверждения.
6. **Защита от случайных нажатий** — по уровням из ТЗ §5.1: обратимое → snackbar «Отменить»; деньги на руки → удержание 0,6 с; необратимое → диалог с глаголом на кнопке. Повтор нажатия < 600 мс игнорируется.
7. **Суммы не переносятся.** `maxLines = 1` + `TextAutoSize.StepBased(minFontSize = 12.sp)`, правая колонка ≤ 50 % ширины.
8. **Шрифты только OFL** (Playfair Display, IBM Plex Sans, IBM Plex Mono) из `res/font`, с `OFL.txt`. Коммерческие шрифты в репозиторий не кладём.
9. **Тексты** — на русском, в `strings.xml` с `plurals` («1 игрок», «2 игрока», «5 игроков»). Никакого lorem и выдуманных цифр в UI.

## Стек

Kotlin 2.x · Jetpack Compose + Material 3 (BOM, последняя стабильная) · `material3-adaptive` · Navigation Compose (типобезопасные маршруты) · Hilt · Room + KSP · DataStore · kotlinx.serialization · kotlinx-datetime · Google Nearby Connections · Vico · JUnit 5, Turbine, Robolectric, Compose UI Test, Roborazzi · ktlint/detekt · Gradle Kotlin DSL + version catalog. minSdk 26, targetSdk — актуальный для Google Play.

Перед добавлением зависимости проверь её актуальную стабильную версию; не тащи библиотеки сверх этого списка без ADR.

## Модули

```
:app                 точка входа, навигация, DI, тема
:core:domain         чистый Kotlin (KMP): модель, правила, движок расчёта (без Android)
:core:data           Room, DataStore, репозитории, экспорт/импорт
:core:transfer       Nearby Connections, формат пакета .feltbook, проверка целостности
:core:odds           пасхалка: оценщик комбинаций, эквити, ауты, шансы банка (чистый Kotlin, KMP)
:core:ui             тема Feltbook, токены, компоненты (клавиатура, фишки, hold-кнопка, sheets)
:feature:game        стол, игроки, закуп/докуп, выход, карточка игрока
:feature:settlement  итог игры, долги
:feature:history     история, статистика
:feature:settings    настройки, резервная копия
:feature:handover    передача комнаты
```

Зависимости только вниз: `feature → core:ui, core:domain, core:data` (плюс `:feature:handover → :core:transfer`, `:feature:settings → :core:odds` для пасхалки); `core:domain` не зависит ни от чего Android. Пакет — `app.feltbook`.

## Команда субагентов

Основная сессия — **техлид**: держит план, режет задачи, раздаёт субагентам, принимает результат. Сама код не пишет, кроме мелких правок склейки.

| Агент | Владеет | Когда звать |
| --- | --- | --- |
| `architect` | `docs/adr`, структура модулей, интерфейсы между слоями | В начале этапа и при любом спорном решении |
| `domain-engine` | `:core:domain` | Формулы, правила, движок расчёта, инварианты |
| `data-layer` | `:core:data` | Room, миграции, репозитории, бэкап |
| `compose-ui` | `:core:ui`, `:feature:*` (UI) | Экраны по макетам, тема, компоненты |
| `transfer` | `:core:transfer`, `:feature:handover` | Nearby, пакет, файл-фолбэк |
| `qa-engineer` | `**/src/test`, `**/src/androidTest` | Тесты по сценариям ТЗ, регрессия |
| `code-reviewer` | — (только читает) | После каждой задачи, до коммита |
| `build-release` | Gradle, CI, подпись, R8, Baseline Profiles | Скелет проекта, CI, релиз |
| `poker-odds` | `:core:odds`, экран калькулятора | Только пасхалка (этап M6) |

Порядок по задаче: `architect` (если нужен интерфейс) → исполнитель → `qa-engineer` → `code-reviewer` → коммит. Независимые задачи (например, `data-layer` и `compose-ui` на моках) запускай параллельно.

**Контракт сдачи** — каждый агент заканчивает ответом:
```
Сделано: <1–3 строки>
Файлы: <список>
Проверено: <какие команды запущены и результат>
Вопросы/риски: <или «нет»>
```

Агент не выходит за свои пути. Нужна правка чужого модуля — описывает её в «Вопросы/риски», техлид решает.

## Этапы

| Этап | Результат | Готово, когда |
| --- | --- | --- |
| M0 Скелет | Модули, Gradle, тема-заглушка, CI | `./gradlew build` зелёный локально и в CI |
| M1 Движок | `:core:domain` полностью | Все примеры ТЗ §3 (в т. ч. сквозной §3.6 и долг §3.7) — тесты зелёные, покрытие домена ≥ 95 % |
| M2 Данные | Room + репозитории + DataStore | Журнал пишется транзакционно, тесты миграций, экспорт→импорт идентичен |
| M3 Стол | Новая игра, стол, закуп/докуп, выход, итог | Сквозной сценарий ТЗ §3.6 проходит в UI-тесте |
| M4 Долги и история | Долги, история, статистика, настройки | Сценарий «ушёл с долгом → вернулся → погасил» в UI-тесте |

| M6 Пасхалка и полировка | Калькулятор шансов, анимации, планшеты, доступность, иконка, релиз | Частоты 7-карточных комбинаций сходятся с эталоном, расчёт ≤ 1 с; чек-лист §9 ТЗ, TalkBack, шрифт 200 %, подписанный AAB |

## Definition of Done

- Поведение совпадает с ТЗ, экран — с макетом (сверено по inline-стилям).
- Тесты на новое поведение есть и зелёные; `ktlintCheck detekt lint` без новых ошибок.
- Нет `Double` в деньгах, нет `UPDATE` журнала, нет захардкоженных цветов и строк.
- Сенсорные цели ≥ 48 dp, `contentDescription` у иконок, суммы читаются TalkBack со знаком и словом.
- `code-reviewer` не нашёл блокеров.

## Git и CI

Conventional Commits (`feat(domain): …`, `fix(ui): …`). Коммит — только после зелёных тестов и ревью, push сразу в `main` (ADR 0002). CI — GitHub Actions на `ubuntu-latest`; красный CI чинится в первую очередь.

## Будущая iOS-версия

`:core:domain` и `:core:odds` — Kotlin Multiplatform (`commonMain`, сейчас цель `jvm()`), без `java.*`/`android.*` (ADR 0001). Бизнес-логика и интерфейсы репозиториев — только там, чтобы iOS переиспользовала их целиком.

## Ресурсы машины

Свободной памяти мало: одновременно — не больше одной Gradle-сборки. Не запускай `connectedDebugAndroidTest` локально без эмулятора; UI-тесты — Robolectric.

## Как запускать этап

Промпт для основной сессии (подставь номер этапа):

```
Ты техлид Feltbook. Этап M<N> из CLAUDE.md.
1. Позови architect: план этапа в docs/plan/m<N>.md, интерфейсы и ADR, если нужны.
2. Раздай задачи из плана агентам-исполнителям; независимые запускай параллельно.
3. После каждой задачи: qa-engineer → code-reviewer. Блокеры — обратно исполнителю.
4. Коммить по задаче после ОДОБРЕНО и зелёного ./gradlew test.
5. В конце: сводка этапа, что готово по критерию из таблицы этапов, открытые вопросы из docs/QUESTIONS.md.
Не выходи за этап. Не меняй docs/SPEC.md — вопросы пиши в docs/QUESTIONS.md.
```
